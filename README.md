# STM32 入门练习：串口控制舵机与 LED

大一上学期的单片机课程练习。两块板子、两个工程，做的是同一件事：
**串口收到文本命令 → 解析 → 控制外设 → 把结果回显给上位机。**

| 目录 | 内容 | 演示 |
|---|---|---|
| `01-servo-uart-control` | 串口输入角度，SG90 舵机转到指定角度 | [舵机演示视频](docs/servo-demo.mp4) |
| `02-led-pattern-uart` | 串口切换三种 LED 模式、调速度、查状态 | — |

---

## 硬件

- **MCU**：STM32F103C8T6 最小系统板（LQFP48，外部晶振 8 MHz）
- **舵机**：SG90，PWM 控制，0.5–2.5 ms 高电平对应 0°–180°
- **LED**：4 只，接 PB0 / PB1 / PB3 / PB11
- **串口**：USART1，115200 8N1，USB-TTL 接 PA9(TX) / PA10(RX)

## 01 · 串口控制舵机

### 功能

上电后串口打印 `SG90 Servo Ready`，之后发送：

```
angle: 90
```

舵机转到 90°，串口回 `Servo moved to 90 deg`。输入不对会有提示：

| 输入 | 回显 |
|---|---|
| `angle: 200` | `Angle range error, only 0-180` |
| `foo` | `Command format error, please retry` |

### 我的理解（如果哪里说错了，请老师指正）

**1. 50 Hz 是怎么来的**

定时器时钟 72 MHz，预分频 `PSC = 71`，所以计数频率是 `72MHz / (71+1) = 1 MHz`，
也就是每 1 µs 计一个数。自动重装值 `ARR = 19999`，一个周期是 20000 个数，
`1MHz / 20000 = 50 Hz`，周期 20 ms——正好是舵机要的频率。

因为 1 个数就是 1 µs，所以高电平时间可以直接用计数表示：
0.5 ms → 500，2.5 ms → 2500。角度换算就成了一行：

```c
int ccr = 500 + angle * 2000 / 180;   // 0°→500, 180°→2500
__HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, ccr);
```

**2. 串口为什么用中断收，而不用 `HAL_UART_Receive`**

中断方式下，`HAL_UART_Receive_IT()` 每次只收 1 个字节，收完自动进回调函数，
我在回调里把它存进缓冲区、再挂起下一次接收。收到 `\r` 或 `\n` 时，
才认为一条完整命令结束，交给解析函数。

这样主循环可以是空的 `while(1){}`，CPU 不浪费在等待上，上位机随时发都能响应。

**3. 缓冲区边界**

`rx_buf` 只有 32 字节，所以 `rx_index >= 30` 时强制截断并清零，
防止一直输入不回车的长字符串把内存写穿。

## 02 · 串口控制 LED 三种模式

### 功能

```
mode:1        流水灯（一个接一个亮）
mode:2        四个一起闪烁
mode:3        呼吸效果
speed:500     周期设为 500 ms（可设 100–2000）
status        查询当前状态 → Mode:1, Speed:500ms
```

### 我的理解

**1. 三种模式用状态机切换**

`current_mode` 存当前是哪种模式，定时器每 1 ms 进一次中断，
在里面判断当前模式、执行对应动作。好处是**切换立即生效**，
不用等当前那轮动画跑完，也不会卡在某个循环里出不来。

**2. 用 `tick_1ms` 计数代替 `HAL_Delay()`**

```c
tick_1ms++;
if (tick_1ms >= speed_ms) { tick_1ms = 0; /* 翻转 LED */ }
```

这一点是我觉得这个工程里最值得记的。如果改成在主循环里 `HAL_Delay(500)`，
灯的效果看着一样，但**串口命令最多要等 500 ms 才有反应**，
而且三个模式得写三套循环。用计数器之后，主循环空着，串口随时能响应，
改速度也只是改一个变量。

**3. 呼吸灯是简化实现**

模式 3 只是把一次"亮—灭"拆成 10 个小格（每格 `speed/10` 毫秒），
效果是慢慢闪，**实际只有全亮和全灭两级**，不是亮度渐变。

代码里还声明了一个 `breathe_val` 变量，本来是打算存 0~999 的亮度值，
但最后没用上，一直留着。

## 已经发现的问题

1. **呼吸灯不是真呼吸**。现在只有亮/灭两级，应该改成 PWM 占空比渐变（配一张亮度表查表输出）。
2. **串口回显是在中断回调里直接发的**（`HAL_UART_Transmit`）。
   我不确定这样会不会拖慢中断响应，还没验证，先记在这里。
3. **`breathe_val` 声明了但没用到**，编译应该有 warning。要么用上，要么删掉。

## 如何编译运行

仓库里**没有 `Drivers/` 目录**（HAL 库和 CMSIS 是 CubeMX 生成的第三方代码，
文件太多，会盖住自己写的部分）。

要完整编译，三步：

1. 用 **STM32CubeMX** 打开对应目录下的 `*.ioc`
2. 菜单 `Project → Generate Code`，会自动重新生成 `Drivers/`
3. 用 **Keil MDK 5** 打开 `MDK-ARM/*.uvprojx`，编译下载

> 手写的逻辑都放在 `/* USER CODE BEGIN */ ... /* USER CODE END */` 之间，
> CubeMX 重新生成代码不会覆盖这部分。
